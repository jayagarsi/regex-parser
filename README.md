# regex-parser
Regular Expression Parser

This is an implementation from scratch of a Regular Expression parser and engine. When executed, the code reads an input regular expression and a string and checks if the string belongs to the language generated by the regular expression. Let us look at the two parts that compose this project: the parsing and the engine. First, the regular expression is parsed and an Abstract Syntax Tree is generated. This tree will then be used by the engine to generate a Non-Determinstic Finite Automaton (NFA) that recognizes the language. Finally, the NFA will be simulated to check if an incoming string belongs to the language or not.

### Regular Expression Parsing
A regular expression is a sequence of characters that represent a match pattern in text (cite wiki). We can have expressions like ```aba|b*``` or ```(ab|ba)+c?```. For te first, strings like ```aba``` or ```bbbb``` would belong to the language represented by this regular expression. More on this can be viewed in the [wikipedia page](https://en.wikipedia.org/wiki/Regular_expression). To parse this type of expressions, we need powerful tools, since the operator ```*``` has more priority than ```|```. Therefore, we can apply concepts from Compiler designs to parse these expressions.

The simplest way one can represent languages is by using [Grammars](https://en.wikipedia.org/wiki/Formal_grammar). We will not go into the details but, the language of regular expressions can be represented by the following LL(1) grammar:

```
expr   : term ('|' term)*       # alternation
term   : factor*                # concatenation
factor : atom postfix?          # star, plus, question operators
postfix : '*' | '+' | '?'
atom    : CHAR | '(' expr ')'   # atom 

CHAR  : ('a'..'z'|'A'..'Z'|'0'..'9');
```
This means that we can implement a [Recursive-Descent Parser](https://en.wikipedia.org/wiki/Recursive_descent_parser). These type of parsers implement mutually recursive methods that call each other to parse the string. The benefit of these parsers is that they run in linear time with respect to the length of the regular expression. Let us see with an example what the parser works. Consider the following regular expression ```((aba|c)*b?)```. Its abstract tree will be the following:

<pre class="mermaid">
flowchart LR
    a("·") --> b("?")
    a --> c("*")
    b --> d((b))
    c --> e("|")
    e --> f((c))
    e --> g("·")
    g --> h((a))
    g --> i("·")
    i --> j((a))
    i --> k((b))
</pre>

Notice how precedence is preserved on each level of the tree.
